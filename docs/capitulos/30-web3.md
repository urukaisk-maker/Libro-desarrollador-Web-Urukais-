## 🌐 ¿Qué es Web3?

**Web3** (o Web 3.0) es un conjunto de tecnologías que buscan una web **descentralizada**, donde los datos y la lógica no dependen de una empresa central, sino de una red de nodos que se validan entre sí.

!!! quote "La analogía del registro público"
    Imagina un **libro de cuentas** que no guarda un banco, sino miles de personas a la vez. Cada vez que alguien anota una transacción, todos los demás la verifican y la copian. Si alguien intenta cambiar una línea del pasado, los demás lo detectan porque no coincide con sus copias. Eso es, en esencia, una **blockchain**.

~~~mermaid
graph LR
    U1[Usuario] --> W[Wallet]
    W --> SC[Smart Contract]
    SC --> BC[(Blockchain)]
    BC --> N1[Nodo 1]
    BC --> N2[Nodo 2]
    BC --> N3[Nodo 3]
~~~

## 🔗 La blockchain como base

Una **blockchain** es una base de datos distribuida, append-only (solo se añade, nunca se borra) y validada por consenso. Cada bloque contiene:

| Campo | Qué guarda |
| :--- | :--- |
| **Transacciones** | Las operaciones (transferencias, llamadas a contratos) |
| **Hash del bloque anterior** | Enlaza con el bloque previo (de ahí "cadena") |
| **Hash propio** | Identifica el bloque |
| **Timestamp** | Cuándo se minó |
| **Nonce** | Prueba de trabajo (en Proof of Work) |

!!! tip "Inmutabilidad práctica"
    Una vez que un bloque tiene suficientes confirmaciones (6 en Bitcoin, 12-64 en Ethereum según el caso), cambiarlo requeriría reescribir toda la cadena desde ese punto. Por eso se dice que es **prácticamente inmutable**.

## 🏛 Smart Contracts

Un **smart contract** es código que se ejecuta en la blockchain. Una vez desplegado, **nadie puede modificarlo** (salvo que el propio contrato tenga funciones de actualización).

~~~solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Contador {
    uint256 public total;

    function incrementar() public {
        total += 1;
    }
}
~~~

- `public total` → variable de estado, legible por cualquiera.
- `incrementar()` → función que modifica el estado. Cuesta **gas** (comisión).
- Desplegarlo cuesta gas. Llamarlo también.

!!! warning "El código es la ley"
    Un bug en un smart contract puede costar millones. No hay "rollback" ni "soporte técnico". Por eso se auditan y se prueban exhaustivamente antes de desplegar. El hackeo de **The DAO** (2016, ~60 M$) es el ejemplo clásico.

## 🧰 El stack típico de Web3

| Capa | Tecnología | Para qué |
| :--- | :--- | :--- |
| **Blockchain** | Ethereum, Polygon, Solana, Arbitrum | Ejecutar contratos |
| **Lenguaje de contratos** | Solidity, Vyper, Rust (Solana) | Escribir smart contracts |
| **Cliente JS** | ethers.js, viem, web3.js | Hablar con la blockchain desde el frontend |
| **Wallet** | MetaMask, Rainbow, WalletConnect | Firmar transacciones |
| **Almacenamiento** | IPFS, Arweave, Filecoin | Guardar archivos descentralizados |
| **Indexado** | The Graph | Consultar datos on-chain eficientemente |
| **Nodo RPC** | Alchemy, Infura, QuickNode | Acceso a la red sin correr un nodo |

!!! tip "Ethereum no es la única"
    Ethereum es la más usada, pero **Polygon** (sidechain de Ethereum) es más barata para empezar. **Solana** es más rápida pero con otro modelo. **Arbitrum/Optimism** son L2 (layer 2) que heredan seguridad de Ethereum con comisiones más bajas.

## 📝 Tu primera DApp en 4 pasos

Una **DApp** (aplicación descentralizada) es un frontend web que habla con smart contracts.

### 1. Conectar la wallet

~~~javascript
import { BrowserProvider } from "ethers";

async function conectar() {
    if (!window.ethereum) {
        alert("Instala MetaMask");
        return;
    }
    const provider = new BrowserProvider(window.ethereum);
    const signer = await provider.getSigner();
    const address = await signer.getAddress();
    console.log("Conectado como", address);
}
~~~

### 2. Leer el estado del contrato

~~~javascript
import { Contract } from "ethers";

const ABI = ["function total() view returns (uint256)"];
const DIRECCION = "0x...";

async function leerTotal(provider) {
    const contrato = new Contract(DIRECCION, ABI, provider);
    const total = await contrato.total();
    console.log("Total:", total.toString());
}
~~~

### 3. Escribir (transacción)

~~~javascript
async function incrementar(signer) {
    const contrato = new Contract(DIRECCION, ABI, signer);
    const tx = await contrato.incrementar();
    await tx.wait();
    console.log("Hecho:", tx.hash);
}
~~~

### 4. Escuchar eventos

~~~javascript
contrato.on("Incrementado", (nuevoTotal) => {
    console.log("Nuevo total:", nuevoTotal.toString());
});
~~~

!!! warning "Gas y comisiones"
    Cada escritura en la blockchain cuesta **gas**. En Ethereum L1 puede ser caro (dólares por transacción). En L2 (Arbitrum, Polygon) es céntimos. Lee siempre el `gasEstimate` antes de enviar.

## ⚠️ Limitaciones y críticas

| Limitación | Detalle |
| :--- | :--- |
| **Escalabilidad** | Ethereum L1 hace ~15 TPS; Visa hace ~24.000 |
| **Coste** | Un swap en L1 puede costar 5-50 € |
| **UX** | Gestionar wallets y gas es complejo para usuarios no técnicos |
| **Seguridad** | Bugs en contratos = pérdida total; phishing de wallets muy común |
| **Regulación** | Cambiante según el país; afecta a tokens y DeFi |
| **Centralización real** | Muchos nodos RPC son de Alchemy/Infura; muchos NFTs están en servidores centrales |
| **Promesas infladas** | "Descentralizar todo" no siempre es viable ni deseable |

!!! warning "Web3 no es la solución a todo"
    Para una app de gestión interna, una base de datos Postgres sigue siendo mejor. Web3 brilla cuando **la confianza entre partes** es el problema, no cuando el problema es la velocidad o la comodidad.

## 🏗 Arquitectura de una DApp

~~~mermaid
graph TD
    U[Usuario] --> F[Frontend React/Next]
    F --> W[MetaMask]
    W --> SC[Smart Contract]
    SC --> BC[(Blockchain)]
    F --> IPFS[IPFS: metadata]
    F --> G[The Graph: queries]
    G --> BC
~~~

- El **frontend** puede ser un Next.js estático.
- La **wallet** firma las transacciones.
- El **contrato** ejecuta la lógica.
- **IPFS** guarda archivos (imágenes, metadata de NFTs).
- **The Graph** indexa eventos para consultas rápidas (evita escanear toda la cadena).

## 🧪 Ejercicio práctico

!!! example "Leer el total de un contador desplegado"
    Tienes un contrato `Contador` desplegado en Sepolia (testnet) en la dirección `0x1234...` con la función `total()`.

    Escribe un script en ethers.js que:

    - Se conecte a Sepolia usando un RPC público (`https://rpc.sepolia.org`).
    - Lea `total()` del contrato.
    - Lo imprima en consola.

??? success "Solución"
    ~~~javascript
    import { JsonRpcProvider, Contract } from "ethers";

    const RPC = "https://rpc.sepolia.org";
    const DIRECCION = "0x1234...";
    const ABI = ["function total() view returns (uint256)"];

    async function main() {
        const provider = new JsonRpcProvider(RPC);
        const contrato = new Contract(DIRECCION, ABI, provider);
        const total = await contrato.total();
        console.log("Total on-chain:", total.toString());
    }

    main().catch(console.error);
    ~~~

    **Nota:** para leer no necesitas wallet ni gas, solo un RPC. Para escribir, sí.

## 🧠 Quiz

!!! question "Comprueba lo aprendido"

??? success "1. ¿Qué diferencia hay entre blockchain y base de datos tradicional?"
    La blockchain es distribuida, append-only, validada por consenso y prácticamente inmutable. Una base de datos tradicional es centralizada, mutable y administrada por una entidad.

??? success "2. ¿Qué es un smart contract?"
    Código que se ejecuta en la blockchain. Una vez desplegado, es inmutable (salvo funciones de actualización explícitas).

??? success "3. ¿Por qué escribir en Ethereum cuesta gas y leer no?"
    Leer (`view`) no modifica el estado ni requiere consenso; escribir sí, y los minadores/validadores cobran por ejecutar y almacenar.

??? success "4. ¿Qué es una DApp?"
    Una aplicación descentralizada: un frontend web que interactúa con smart contracts mediante una wallet (MetaMask, etc.).

??? success "5. ¿Cuándo NO tiene sentido usar Web3?"
    Cuando la confianza entre partes no es el problema (ej. apps internas, CRUDs, dashboards). Una base de datos tradicional es más rápida, barata y sencilla.

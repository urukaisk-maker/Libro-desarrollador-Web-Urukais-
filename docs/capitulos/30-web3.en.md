## 🌐 What is Web3?

**Web3** (or Web 3.0) is a set of technologies aiming for a **decentralized** web, where data and logic do not depend on a central company, but on a network of nodes that validate one another.

!!! quote "The public ledger analogy"
    Imagine an **account ledger** kept not by a bank, but by thousands of people at once. Every time someone records a transaction, everyone else verifies and copies it. If someone tries to alter a past line, the others detect it because it doesn't match their copies. That is, in essence, a **blockchain**.

~~~mermaid
graph LR
    U1[User] --> W[Wallet]
    W --> SC[Smart Contract]
    SC --> BC[(Blockchain)]
    BC --> N1[Node 1]
    BC --> N2[Node 2]
    BC --> N3[Node 3]
~~~

## 🔗 Blockchain as the Foundation

A **blockchain** is a distributed, append-only (only added to, never deleted) database validated by consensus. Each block contains:

| Field | What It Stores |
| :--- | :--- |
| **Transactions** | The operations (transfers, contract calls) |
| **Previous block hash** | Links to the prior block (hence "chain") |
| **Own hash** | Identifies the block |
| **Timestamp** | When it was mined/validated |
| **Nonce** | Proof of work (in Proof of Work) |

!!! tip "Practical immutability"
    Once a block has enough confirmations (6 in Bitcoin, 12-64 in Ethereum depending on the context), altering it would require rewriting the entire chain from that point on. That is why it is called **practically immutable**.

## 🏛 Smart Contracts

A **smart contract** is code that runs on the blockchain. Once deployed, **nobody can modify it** (unless the contract itself includes upgrade functions).

~~~solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract Contador {
    uint256 public total;

    function incrementar() public {
        total += 1;
    }
}
~~~

- `public total` → state variable, readable by anyone.
- `incrementar()` → function that modifies state. Costs **gas** (fee).
- Deploying it costs gas. Calling it also does.

!!! warning "Code is law"
    A bug in a smart contract can cost millions. There is no "rollback" or "customer support". That's why they are audited and thoroughly tested before deployment. **The DAO** hack (2016, ~$60M) is the classic example.

## 🧰 The Typical Web3 Stack

| Layer | Technology | Purpose |
| :--- | :--- | :--- |
| **Blockchain** | Ethereum, Polygon, Solana, Arbitrum | Execute contracts |
| **Contract language** | Solidity, Vyper, Rust (Solana) | Write smart contracts |
| **JS client** | ethers.js, viem, web3.js | Talk to the blockchain from the frontend |
| **Wallet** | MetaMask, Rainbow, WalletConnect | Sign transactions |
| **Storage** | IPFS, Arweave, Filecoin | Store decentralized files |
| **Indexing** | The Graph | Query on-chain data efficiently |
| **RPC node** | Alchemy, Infura, QuickNode | Network access without running a node |

!!! tip "Ethereum isn't the only one"
    Ethereum is the most widely used, but **Polygon** (an Ethereum sidechain) is cheaper to get started with. **Solana** is faster with a different model. **Arbitrum/Optimism** are L2s (Layer 2) that inherit Ethereum's security with lower fees.

## 📝 Your First DApp in 4 Steps

A **DApp** (decentralized application) is a web frontend that talks to smart contracts.

### 1. Connect the Wallet

~~~javascript
import { BrowserProvider } from "ethers";

async function conectar() {
    if (!window.ethereum) {
        alert("Instala MetaMask");
        return;
    }
    const provider = new BrowserProvider(window.ethereum);
    const signer = await provider.getSigner();
    const address = await signer.getAddress();
    console.log("Conectado como", address);
}
~~~

### 2. Read Contract State

~~~javascript
import { Contract } from "ethers";

const ABI = ["function total() view returns (uint256)"];
const DIRECCION = "0x...";

async function leerTotal(provider) {
    const contrato = new Contract(DIRECCION, ABI, provider);
    const total = await contrato.total();
    console.log("Total:", total.toString());
}
~~~

### 3. Write (Transaction)

~~~javascript
async function incrementar(signer) {
    const contrato = new Contract(DIRECCION, ABI, signer);
    const tx = await contrato.incrementar();
    await tx.wait();
    console.log("Hecho:", tx.hash);
}
~~~

### 4. Listen to Events

~~~javascript
contrato.on("Incrementado", (nuevoTotal) => {
    console.log("Nuevo total:", nuevoTotal.toString());
});
~~~

!!! warning "Gas and fees"
    Every write to the blockchain costs **gas**. On Ethereum L1 it can be expensive (dollars per transaction). On L2s (Arbitrum, Polygon) it's cents. Always check `gasEstimate` before sending.

## ⚠ Limitations and Criticisms

| Limitation | Detail |
| :--- | :--- |
| **Scalability** | Ethereum L1 does ~15 TPS; Visa does ~24,000 |
| **Cost** | A swap on L1 can cost €5-€50 |
| **UX** | Managing wallets and gas is complex for non-technical users |
| **Security** | Contract bugs = total loss; wallet phishing is very common |
| **Regulation** | Varies by country; affects tokens and DeFi |
| **De facto centralization** | Many RPC nodes run on Alchemy/Infura; many NFTs sit on central servers |
| **Inflated claims** | "Decentralizing everything" isn't always viable or desirable |

!!! warning "Web3 isn't the answer to everything"
    For an internal management app, a Postgres database is still better. Web3 shines when **trust between parties** is the problem—not when the problem is speed or convenience.

## 🏗 DApp Architecture

~~~mermaid
graph TD
    U[User] --> F[Frontend React/Next]
    F --> W[MetaMask]
    W --> SC[Smart Contract]
    SC --> BC[(Blockchain)]
    F --> IPFS[IPFS: metadata]
    F --> G[The Graph: queries]
    G --> BC
~~~

- The **frontend** can be a static Next.js app.
- The **wallet** signs transactions.
- The **contract** executes logic.
- **IPFS** stores files (images, NFT metadata).
- **The Graph** indexes events for fast queries (avoids scanning the entire chain).

## 🧪 Hands-On Exercise

!!! example "Read the total of a deployed counter"
    You have a `Contador` contract deployed on Sepolia (testnet) at address `0x1234...` with the `total()` function.

    Write an ethers.js script that:

    - Connects to Sepolia using a public RPC (`https://rpc.sepolia.org`).
    - Reads `total()` from the contract.
    - Logs it to the console.

??? success "Solution"
    ~~~javascript
    import { JsonRpcProvider, Contract } from "ethers";

    const RPC = "https://rpc.sepolia.org";
    const DIRECCION = "0x1234...";
    const ABI = ["function total() view returns (uint256)"];

    async function main() {
        const provider = new JsonRpcProvider(RPC);
        const contrato = new Contract(DIRECCION, ABI, provider);
        const total = await contrato.total();
        console.log("Total on-chain:", total.toString());
    }

    main().catch(console.error);
    ~~~

    **Note:** reading doesn't require a wallet or gas, only an RPC. Writing does.

## 🧠 Quiz

!!! question "Check what you learned"

??? success "1. What is the difference between a blockchain and a traditional database?"
    A blockchain is distributed, append-only, consensus-validated, and practically immutable. A traditional database is centralized, mutable, and managed by an entity.

??? success "2. What is a smart contract?"
    Code that runs on the blockchain. Once deployed, it is immutable (barring explicit upgrade functions).

??? success "3. Why does writing to Ethereum cost gas while reading does not?"
    Reading (`view`) doesn't modify state or require consensus; writing does, and miners/validators charge for execution and storage.

??? success "4. What is a DApp?"
    A decentralized application: a web frontend that interacts with smart contracts through a wallet (MetaMask, etc.).

??? success "5. When does using Web3 NOT make sense?"
    When trust between parties isn't the problem (e.g., internal apps, CRUDs, dashboards). A traditional database is faster, cheaper, and simpler.

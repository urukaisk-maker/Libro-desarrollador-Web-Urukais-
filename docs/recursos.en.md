## 📚 Recommended books

These are the books that have most influenced how I write code and teach:

### Fundamentals

| Book | Author | Level | Why read it |
| :--- | :--- | :--- | :--- |
| *HTML and CSS: Design and Build Websites* | Jon Duckett | 🟢 Beginner | The most visual and accessible book to get started. |
| *Eloquent JavaScript* | Marijn Haverbeke | 🟡 Intermediate | JavaScript explained with clarity and depth. [Free online](https://eloquentjavascript.net/). |
| *You Don't Know JS* (series) | Kyle Simpson | 🟠 Advanced | To understand JS under the hood. [Free on GitHub](https://github.com/getify/You-Dont-Know-JS). |
| *CSS: The Definitive Guide* | Eric A. Meyer | 🟠 Advanced | A comprehensive reference for CSS. |

### Architecture and best practices

| Book | Author | Level | Why read it |
| :--- | :--- | :--- | :--- |
| *Clean Code* | Robert C. Martin | 🟠 Advanced | Clean code practices and trade-offs. |
| *Refactoring* | Martin Fowler | 🔴 Professional | How to improve existing code without breaking behavior. |
| *Designing Data-Intensive Applications* | Martin Kleppmann | 🔴 Professional | The go-to book on data systems and distributed architectures. |
| *The Pragmatic Programmer* | Hunt & Thomas | 🟡 Intermediate | The book I have gifted the most. Teaches how to think like a developer. |

### Design and UX

| Book | Author | Level | Why read it |
| :--- | :--- | :--- | :--- |
| *Refactoring UI* | Adam Wathan & Steve Schoger | 🟡 Intermediate | How to make your interfaces look polished and intentional. |
| *Don't Make Me Think* | Steve Krug | 🟡 Intermediate | Usability principles explained with humor and clarity. |
| *Design Systems* | Alla Kholmatova | 🟣 Expert | How to build scalable design systems. |

## 💡 How to use these resources

!!! tip "Don't spread yourself too thin"
    With so many resources available, it is easy to fall into analysis paralysis. My advice:

1. **Pick one resource per category** (one book, one channel, one set of docs).
2. **Finish it** before starting another.
3. **Practice** by building your own projects—do not just consume content.
4. **Do not hoard courses**: finishing one beats starting ten.

!!! note "Missing a resource?"
    If you know a resource that belongs here, open an [issue on GitHub](https://github.com/urukaisk-maker/Libro-desarrollador-Web-Urukais-/issues/new) or send a PR. Resources are reviewed every week.
